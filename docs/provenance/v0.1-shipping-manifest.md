# v0.1 shipping manifest

SYSTEM ERROR'S THE LOOP v0.1 ships all 31 portable `SKILL.md` packages. Setup
installs the integrity-pinned pack and its offline toolkit, Doctor verifies the
installed result, and every packaged capability includes a bundled fallback that a
compatible harness can execute without a separately installed specialist.

## Protocols

All ten protocols are required because `the-loop-auto` is not safe without them:

1. Stage contracts.
2. Skill routing.
3. Code and non-code tracks.
4. Workflow dispatch.
5. Autonomy policy.
6. Run state and leases.
7. Issue ledger.
8. Evidence contract.
9. Watcher contract.
10. Harness capability map.

## Harness adapters

- Codex: project skills under `.agents/skills`, explicit invocation through Codex skill selection, and no assumption that a named subagent API exists.
- Claude Code: project skills under `.claude/skills` or a thin plugin adapter, with Claude-only frontmatter kept out of portable core files.
- Kimi Code: project skills under `.agents/skills` or `.kimi-code/skills`, with manual invocation supported through `/skill:<name>`.
- OpenCode: project skills under `.agents/skills` or `.opencode/skills`, with skill permissions checked by the doctor.

These four adapters are implemented, but their live behavior remains unverified. The
official DeepSeek Harness 0.1.0-rc.6 has been evaluated in an isolated environment and
documents a compatible `.agents/skills` root. THE LOOP does not yet implement a DSH
adapter or accept `dsh` in Setup, Doctor or schemas. It is therefore an evaluated
candidate, not a fifth supported harness.

## Required repository material

- Portable `SKILL.md` packages with only standard cross-harness frontmatter.
- Protocol documents and machine-readable schemas.
- An exact SHA-256 release-integrity inventory covering every offline-toolkit file;
  Setup, Doctor and deterministic conformance fail closed on any mismatch.
- Setup and doctor commands.
- Synthetic fixtures and conformance tests for the four implemented adapters.
- `PROVENANCE.md`, per-skill records, contribution guidance and release checks.
- A versioned launch manifest for the separately owned static page at `https://systemerror.app/the-loop`, with repository, quickstart, status, provenance, example and CTA facts kept truthful until that page passes its own delivery gate.

## Maturity and activation gates

The 19 expansion packages are included, not deferred from the manifest. Parallel has
repository-tested lane primitives. The other 18 currently provide portable fallback
contracts only. The following integration gates still apply:

`the-loop-parallel` requires disjoint lane ownership, independent evidence and one
integration owner.

`the-loop-cloud` requires a generic restricted-environment contract with no private
remote infrastructure assumptions.

`the-loop-endless` runtime activation remains blocked until bounded Auto, durable
state, leases, heartbeat, permissions, budgets and an external kill switch pass
failure and recovery tests.

`the-loop-watch` requires the read-only watcher contract and must never take a worker
lease.

`the-loop-control` needs proved runtime controls and a hard authority/recovery handoff.

`the-loop-autonomy` needs proven grant visibility, expiry and revocation controls.

`the-loop-skill-planner` needs safe planning logic, capability proposal ranking and
bounded selector evidence.

`the-loop-skill-creator` needs provenance-aware upstream routing and an explicit
self-modification approval boundary.

`portfolio-review` needs a generic implementation without private portfolio intelligence.

`live-state-preflight` needs generic, provider-neutral state probes and namespace-safe
bootstrap defaults.

`idea-to-brief` and `stack-summary` need clean public planning and memory summarization
fallbacks.

`bootstrap-agent-context`, `pre-commit-review`, `feature-tracker`, `decision-log`,
`handoff`, `retrospective`, and `session-summary` require live routing evidence before
their behavior can be advertised as supported.

`the-loop-endless` is not runtime-eligible until bounded Auto, durable state, leases,
heartbeat, permissions, budgets and an external kill switch pass live failure and
recovery tests.

The landing page is a required launch asset, not part of the skill kernel. Its production deployment remains a separate human gate.
