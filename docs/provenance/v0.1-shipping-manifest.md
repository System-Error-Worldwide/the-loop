# Recommended v0.1 shipping manifest

v0.1 is a bounded, local-first kernel. It proves one attended run and one bounded automatic mission before adding supervision or parallelism.

## Skills

| Skill | Classification | v0.1 role |
| --- | --- | --- |
| `the-loop-setup` | system-error-original | Detect harnesses and install the portable pack without overwriting user files. |
| `the-loop-doctor` | system-error-original | Report discovery, collisions, permissions and runtime readiness. |
| `the-loop` | system-error-rewrite | Run one attended lifecycle with explicit stage boundaries. |
| `the-loop-auto` | system-error-rewrite | Drive one bounded asset to green or a configured gate. |
| `strategize` | system-error-rewrite | Produce a decision brief and success gate. |
| `spec-pack` | system-error-rewrite | Produce the required specification set before implementation. |
| `build` | system-error-rewrite | Implement only an approved slice. |
| `test` | system-error-rewrite | Produce reproducible evidence and issues. |
| `resolve` | system-error-rewrite | Close ledger issues with regression evidence. |
| `health-check` | system-error-rewrite | Reactively detect breakage and feed bounded work. |
| `audit` | system-error-rewrite | Proactively detect drift and feed bounded work. |
| `close` | system-error-rewrite | Reconcile run state and leave a faithful handoff. |

## Protocols

All ten protocols are required because `the-loop-auto` is not safe without them:

1. Stage contracts.
2. Skill routing.
3. Code and non-code tracks.
4. Workflow dispatch.
5. Autonomy policy.
6. Run state and leases.
7. Issue ledger.
8. Evidence contract.
9. Watcher contract.
10. Harness capability map.

## Harness adapters

- Codex: project skills under `.agents/skills`, explicit invocation through Codex skill selection, and no assumption that a named subagent API exists.
- Claude Code: project skills under `.claude/skills` or a thin plugin adapter, with Claude-only frontmatter kept out of portable core files.
- Kimi Code: project skills under `.agents/skills` or `.kimi-code/skills`, with manual invocation supported through `/skill:<name>`.
- OpenCode: project skills under `.agents/skills` or `.opencode/skills`, with skill permissions checked by the doctor.

## Required repository material

- Portable `SKILL.md` packages with only standard cross-harness frontmatter.
- Protocol documents and machine-readable schemas.
- An exact SHA-256 release-integrity inventory covering every offline-toolkit file;
  Setup, Doctor and deterministic conformance fail closed on any mismatch.
- Setup and doctor commands.
- Synthetic fixtures and four-harness conformance tests.
- `PROVENANCE.md`, per-skill records, contribution guidance and release checks.
- A versioned launch manifest for the separately owned static page at `https://systemerror.app/the-loop`, with repository, quickstart, status, provenance, example and CTA facts kept truthful until that page passes its own delivery gate.

## Explicitly deferred

`the-loop-parallel`, `the-loop-cloud`, `the-loop-endless`, `the-loop-watch`, `the-loop-control`, `the-loop-autonomy`, `portfolio-review`, adaptive skill planning and creation, and the remaining supporting utilities.

`the-loop-endless` is not eligible until bounded Auto, durable state, leases, heartbeat, permissions, budgets and an external kill switch pass failure and recovery tests.

The landing page is a required launch asset, not part of the skill kernel. Its production deployment remains a separate human gate.
